# MedoOffline — Decision Log & Open Issues

## Phase 1 — Parser + Fixtures

### DOM Analysis (from fixture spec, 2026-10-08)

**Real site URL pattern**: `/qbank/topic-id-<N>` — one question per page, paginated.

**Stem extraction strategy**:
- Target `#q-stem-container` by id (stable).
- NEVER select by class name — all class names are randomised per page load.
- Decoy blocks: sibling `<div>` elements with random two-class names containing
  text of OTHER questions (glued together, e.g. `"درمانکاتونیاصحیح"`).
  They are hidden by obfuscated CSS (`display:none`) but the CSS class is random.
- The `inert` attribute is NOT a discriminator — both real content and decoys
  can carry it.
- In Playwright (live scraping), use `page.evaluate()` with `getComputedStyle`
  to check `display`, `visibility`, bounding box, and offset position before
  reading text.

**Option ground truth**: `span.encoded-option[data-encoded-text]` (base64).
  - `data-decoded="true"` is present when already decoded by JS.
  - Raw inner text has invisible chars injected — always use the base64 value.
  - IDs: `label{i}`, `input[value={i}]`, `prograssBar{i}` (note spelling: "prograssBar").

**Vote percentages**: `#prograssBar{i}[data-encoded-percent]` — base64 integer string.
  - Bars are `display:none` before submit, `display:block` after.

**Answer detection** (two independent strategies, colour is authority):
  1. Marker: regex `تایید\s*گزینه\s*(\d)` in `#block-b` text — works BEFORE submit.
  2. Colour: after submit, `label{i}` gets `color: rgb(48,127,226)` (correct)
     or `color: rgb(239,64,86)` (wrong).
  - Record `answer_source = marker | color | both | unknown`.
  - If both and they disagree: use colour, log mismatch for `medo verify`.

**Explanation block**: `#block-b` — `display:none` before submit, `display:block` after.
  - Content is already in the DOM before submit (just hidden), so marker is parseable
    without clicking submit.
  - `#image-container img` — mindmap images on `s3-strg.medofast.ir`.
  - Watermark `<div class="watermark">` inside — must be stripped.

**Invisible characters**: U+200B–200F, U+2060–2064, U+FEFF injected between
  letter runs. Strip before any string comparison or storage.

**Noise to ignore**: `#pointPopup`, `#yektanet-ad`, `#mediaad`,
  junk `data-*` attributes (base64 CSS fragments), `id="end"` duplicate buttons.

**Navigation**: `button[data-nav-role="next"][data-page="N"]` — page 1 prev is
  disabled (class `turned-off`).

### Scraping decisions
- 1 request at a time, random delay 1.5–3 s (uniform), no parallelism.
- Exponential backoff on 429/503; stop on captcha.
- WAL mode SQLite; one transaction per question.
- `scrape_state` table tracks `(topic_id, last_page)` for resume.
- SIGINT/SIGTERM: finish current question, flush, print summary, exit cleanly.

### Answer submission strategy
- Parse marker first (available without submitting).
- If `correct_index` still None after marker parse, submit option 1 and read colour.
- Never re-login, never reset session, never spoof cookies.
- Detect quota/limit message → set `explanation_status = locked`, stop, report.

### Image handling
- Download to `data/assets/<sha1>.<ext>`.
- Mindmaps: convert to WebP, max 1600 px wide (Pillow).
- Dedup by URL and sha1; never download twice.
- Block ads/trackers/fonts in Playwright request interception.

### Phase 1 fixture approach
- Synthetic fixtures generated by `scripts/make_fixtures.py` matching exact DOM.
- When real MHTML files are available, drop them into `tests/fixtures/` as
  `before.mhtml` / `after.mhtml` — tests run identically against real content.
- Fixture note: real site injects invisible chars into visible text (DOM);
  our fixtures replicate this exactly.

## Stack choices
| Concern | Choice | Rationale |
|---|---|---|
| HTML parsing in tests | stdlib `html.parser` | No deps needed for Phase 1; Playwright provides richer DOM for live scraping |
| DB | SQLite WAL + FTS5 | Single-file, zero-server, resumable, full-text search |
| Text norm | stdlib `unicodedata` | No external libs for pure normalisation |
| PDF | Playwright `page.pdf()` | Best RTL + mixed-script rendering |
| Web app | Vanilla JS, file:// compatible | No CDN, works offline from disk |

### 2. Database Schema Reference (`medo/db.py`)

- **`categories`**:
  Hierarchical category and topic tree (`id`, `parent_id`, `kind`, `title`, `source_url`, `question_count`).
- **`questions`**:
  Stores parsed questions uniquely indexed by `content_hash` (SHA-256 of normalized stem + options).
  - Columns: `id`, `topic_id`, `source_url`, `source_page`, `ordinal`, `content_hash`, `stem_html`, `stem_text`, `options_json`, `correct_index`, `answer_source`, `vote_percent_json`, `explanation_html`, `explanation_text`, `explanation_status`, `has_images`, `bookmarked`, `user_selected_option`.
- **`assets`**:
  Deduplicated storage keyed by content SHA-1 (`sha1`, `original_url`, `local_path`, `mime`, `bytes_size`, `role`).
- **`question_assets`**:
  Many-to-many junction table between questions and downloaded media files.
- **`scrape_state`**:
  Resumable checkpoint tracking per topic (`topic_id`, `last_page`, `total_pages`, `status`, `error_message`, `updated_at`).
  Status values: `'idle'`, `'running'`, `'completed'`, `'paused'`, `'rate_limited'`, `'captcha'`, `'auth_required'`.
- **`questions_fts`**:
  FTS5 virtual table synchronized via SQLite triggers (`questions_ai`, `questions_ad`, `questions_au`) for rapid Persian keyword search across stem, explanation, and option text.

### 3. DOM Extraction & Obfuscation Bypasses

1. **Randomized CSS Classes**:
   The live website randomizes all class names on every page load to defeat simple class-based scrapers. All parsing logic strictly anchors on stable HTML element IDs:
   - `#q-stem-container`: Real question stem.
   - `#label1` through `#label5`: Question options.
   - `#prograssBar1` through `#prograssBar5`: Percentage distribution bars (note the spelling with double 's').
   - `#block-b`: Explanation container.
   - `#image-container`: Mindmaps and medical illustrations.
2. **Decoy Stem Sibling Blocks**:
   Decoys carry obfuscated random classes and contain concatenated text from other questions. They are eliminated by targeting only `#q-stem-container`.
3. **Invisible Character Poisoning**:
   The website injects zero-width characters (U+200B through U+200F, U+2060 through U+2064, U+FEFF) inside words. The parser strips them via regex `[\u200b-\u200f\u2060-\u2064\ufeff]` before any text processing.
4. **Base64 Ground Truth**:
   The plain text in option spans is noisy; the true text is decoded from `span.encoded-option[data-encoded-text]`. Percentages are decoded from `data-encoded-percent`.
5. **Answer Authority**:
   - Primary: Marker regex `تایید\s*گزینه\s*(\d)` inside `#block-b` (available prior to submitting).
   - Secondary: Label inline color `color: rgb(48, 127, 226)` (correct) vs `color: rgb(239, 64, 86)` (wrong) after submitting option 1. Color takes precedence in case of any discrepancy.

### 4. Browser & Playwright Launch Strategy (`medo/browser.py`)

- Downloading Playwright Chromium (`~200 MB`) can fail or hang on restricted network connections (`cdn.playwright.dev`).
- `medo/browser.py` automatically detects locally installed system browsers on Windows:
  1. `channel="chrome"` (`C:\Program Files\Google\Chrome\Application\chrome.exe`)
  2. `channel="msedge"` (`C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`)
  3. Bundled Chromium (fallback)
- This ensures 100% offline capability and zero-install execution for Playwright tasks.

---

### 5. Media Pipeline (`medo/assets.py`)

- Images are downloaded once, hashed with SHA-1, and saved to `data/assets/<sha1>.<ext>`.
- Mindmap diagrams are converted to WebP with a maximum width of 1600 px using Pillow, maintaining high visual clarity while reducing disk storage by ~70%.
- Duplicate image URLs across questions reuse the existing asset record in `data/assets/`.

### 6. Interactive Web Application (`medo/web/`)

- **Design Aesthetic**:
  - Medical glassmorphic interface with tailored dark theme (`#0a0e17` base) and light theme toggle.
  - Direction: Right-to-Left (`dir="rtl"`), Vazirmatn typography, Persian digit rendering (`۰-۹`).
- **Interactive Exam Mode**:
  - Clicking an option reveals whether it is correct (emerald `#10b981`) or incorrect (crimson `#f43f5e`).
  - Animated vote percentage progress bars slide in from right to left.
  - Explanation card expands smoothly below the question.
  - Mindmap images support click-to-zoom in a lightbox modal.
- **Palette & Navigation**:
  - Question jump palette showing question states: grey (unanswered), green (correct), red (incorrect), gold star (bookmarked).
  - Filter tabs: "All", "Answered", "Bookmarked".
  - Keyboard shortcuts:
    - `1` - `5`: Select option
    - `ArrowLeft` / `j`: Next question
    - `ArrowRight` / `k`: Previous question
    - `b`: Toggle bookmark
    - `e`: Toggle explanation accordion
    - `/`: Focus search input
    - `Esc`: Close image zoom / exit search

### 7. Printable PDF Test Book Generator (`medo/pdf.py`)

- Uses Jinja2 template (`medo/templates/book.html`) and Playwright's `page.pdf()`.
- Structure:
  1. Header with topic title and question count.
  2. Part 1: Clean questions with four options (الف، ب، ج، د), notes margins, and `page-break-inside: avoid` per question.
  3. Part 2: Quick answer key matrix table.
  4. Part 3: Detailed explanations with embedded images (converted to base64 data URIs for true offline rendering).
- Standard A4 layout with page numbering header/footer.

### 8. CLI Usage Quick Reference

```powershell
# 1. Login interactively (opens browser, saves session cookies to data/storage_state.json)
python -m medo.cli login

# 2. Scrape a topic politely (resumable, 1.5–3s delay, auto-saves to data/medo.db)
python -m medo.cli scrape --topic 79

# 3. View database health and statistics
python -m medo.cli stats

# 4. Verify database integrity (checks for missing answers or invalid options)
python -m medo.cli verify

# 5. Launch interactive offline web practice server
python -m medo.cli serve --port 8080

# 6. Export printable PDF test book
python -m medo.cli export-pdf --topic 79 --output dist/medo_test_book.pdf

# 7. Export standalone static web bundle (openable without Python)
python -m medo.cli export-web --output dist/

# 8. Import MHTML fixtures for offline testing
python -m medo.cli import-fixtures
```
